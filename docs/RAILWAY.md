# Запуск бота на Railway (24/7)

Бот на Railway работает круглосуточно, даже когда компьютер выключен. Код Railway берёт прямо из репозитория GitHub и сам обновляет бота после каждого `git push` в ветку `main`. База хранится на постоянном диске (Volume).

## Что уже готово в коде
- `railway.json`: команда запуска `python main.py`, перезапуск при сбое.
- `requirements.txt`: aiogram 3.32+. `.python-version`: Python 3.13.
- Переменная `DATA_DIR`: папка для базы. На Railway это `/data` (туда подключается Volume).
- «💾 Резервная копия» в главном меню: файл базы присылается в Telegram, восстанавливается отправкой файла с подписью `/restore`. Каждый день в 23:00 бот сам присылает копию владельцу.
- `.env` и `*.db` в репозиторий не попадают. Токен задаётся в настройках Railway.

## Шаги

**1. Копия базы с компьютера.** Пока бот работает на компьютере: «💾 Резервная копия» → «📤 Прислать копию сейчас». Сохранить присланный файл `.db`.

**2. Остановить бота на компьютере.** Две копии одного бота мешают друг другу.

**3. Аккаунт.** Зарегистрироваться на [railway.com](https://railway.com) через GitHub (кнопка «Login with GitHub») и выбрать план Hobby. Актуальные цены: railway.com/pricing.

**4. Проект из GitHub.** New Project → Deploy from GitHub repo → разрешить Railway доступ к репозиторию `MyPC-parts-TgBot` → выбрать его. Первый запуск упадёт с ошибкой «Не задан BOT_TOKEN» — это нормально, переменных ещё нет.

**5. Volume.** В проекте: правой кнопкой по сервису (или Ctrl+K → «Volume») → Add Volume → выбрать сервис бота, Mount path: `/data`.

**6. Переменные.** Сервис → Variables → New Variable:
- `BOT_TOKEN` — токен от @BotFather;
- `OWNER_ID` — ваш числовой id;
- `DATA_DIR` — `/data`.

Нажать Deploy (или «Apply changes»). Бот перезапустится.

**7. Проверка.** Deployments → View logs: должны быть строки `База: /data/warehouse.db` и `Run polling for bot @...`. В Telegram — `/start`.

**8. Перенос базы.** Отправить боту файл из шага 1, в подписи — `/restore`. Бот ответит «✅ База восстановлена: деталей в ней N».

## Второй пользователь
В Variables изменить `OWNER_ID` на несколько id через запятую: `ваш_id,его_id`. Первым должен стоять ваш id: владельцу приходят ежедневные копии, и только он может делать `/restore`. Railway перезапустит бота сам.

## Обновление бота потом
Правки кода → коммит → `git push`. Railway сам соберёт и перезапустит бота, база на Volume не пропадает.

## Если что-то не так
- В логах `База: /app/warehouse.db` — не задан `DATA_DIR=/data`: база пропадёт при следующем обновлении.
- `Conflict: terminated by other getUpdates request` — где-то ещё запущена вторая копия бота (например, на компьютере).
